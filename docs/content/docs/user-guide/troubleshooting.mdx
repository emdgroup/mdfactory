## Installation issues

<Accordions type="single" collapsible>
<Accordion title="Import errors after installation">

Activate the environment and reinstall in editable mode:

```bash
conda activate mdfactory
pip install -e .
```

</Accordion>
<Accordion title="OpenMM import errors during build">

OpenMM is used during build-time compression and equilibration:

```bash
conda install -c conda-forge openmm
```

</Accordion>
</Accordions>

## Configuration and sync

<Accordions type="single" collapsible>
<Accordion title="Backend database or CSV file not initialized">

The sync layer expects initialized backend storage. Run the appropriate init command before push or pull:

```bash
mdfactory sync init systems
mdfactory sync init analysis
mdfactory sync init artifacts
```

</Accordion>
<Accordion title="Foundry setup fails">

Re-run the interactive setup and validation flow:

```bash
mdfactory sync init config
mdfactory sync init check
```

This is only meaningful when `[database] TYPE = foundry`.

</Accordion>
</Accordions>

## Build issues

<Accordions type="single" collapsible>
<Accordion title="Bilayer validation errors">

Use:

```bash
mdfactory check-csv input.csv
```

For bilayer rows, this runs the current buildability checks in addition to model validation.

</Accordion>
<Accordion title="Force field 'amber14sb' requires GROMACS >= 2026">

`parametrization: amber` uses the `amber14sb.ff` that ships with GROMACS 2026 and later. The check
runs when the protein is prepared at build time, and again on the compute node before the first
`grompp` of `mdfactory simulate`.

- Locally: run mdfactory inside the pixi `gmx` (CPU) or `gmx-cuda` (GPU) environment, for example
  `pixi run -e gmx mdfactory build ...`, or set `[gromacs] GMX_PATH` in the config to a
  GROMACS 2026 binary.
- On SLURM: cluster modules (`gromacs/2024.x`) do not satisfy the check. Activate the pixi
  environment on the workers with `environment.extra_init`; see
  [examples/pipeline/slurm_gpu.yaml](https://github.com/emdgroup/mdfactory/blob/main/examples/pipeline/slurm_gpu.yaml).
- Also run the controller (`mdfactory ... --slurm`) from the same environment, otherwise Parsl
  versions of controller and workers can differ.

</Accordion>
<Accordion title="Protein builds fail in pdb2gmx or on box size">

- **Multi-chain structures.** `proteinbox` needs `chains` to list every chain; `protein_mixedbox`
  needs `merge_all: true` and no `chains`.
- **Box too small.** For `protein_mixedbox`, `sizing.box_size` (or the box implied by
  `count_density`) must be at least the protein extent plus 2 × `padding`. The error states the
  minimum edge.
- **Residue naming.** `disulfide_bonds` and `protonation_states` use the residue names and numbers of
  the input PDB (for example `CYS6`, `HIS15`); an entry that matches no residue is an error.
- **Missing residues** in the structure are handled by PDBFixer: missing internal segments are
  modeled and terminal tails dropped, with a warning for every segment.
- **Net charge.** The build ends with a `grompp` check. With `neutralize: false`, only the
  net-charge warning is tolerated.

</Accordion>
<Accordion title="Large systems fail during compression">

The build code uses OpenMM-based compression or equilibration steps. For difficult systems, start with smaller molecule counts or a less aggressive target density and verify the input chemistry first.

</Accordion>
</Accordions>

## Workflow issues

<Accordions type="single" collapsible>
<Accordion title="Simulate cannot find build files">

`mdfactory simulate` requires each simulation directory to contain the standard build outputs (`system.pdb`, `topology.top`, and `.mdp` files). Common causes:

- The build step (`mdfactory build`) did not complete successfully for some hashes.
- The `--source` path does not point to the directory containing the hash subdirectories.
- Use `--dry-run` to preview which directories would be simulated and which are skipped.

```bash
mdfactory simulate output_dir/ --slurm gpu.yaml --dry-run
```

</Accordion>
<Accordion title="Checkpoint detection skips stages unexpectedly">

In `--checkpoint auto` mode (the default), MDFactory validates trajectory integrity using frame counts. A stage is skipped when its output `.gro` file and prerequisite checkpoint (`.cpt`) both exist and pass validation.

To force re-execution of all stages:

```bash
mdfactory simulate output_dir/ --slurm gpu.yaml --checkpoint force
```

To skip validation and rely only on file existence:

```bash
mdfactory simulate output_dir/ --slurm gpu.yaml --checkpoint skip
```

</Accordion>
<Accordion title="Stale checkpoints after a killed job">

When a SLURM job is cancelled mid-flight, checkpoint files (`.cpt`) may be left behind
without corresponding trajectory files. Use `--clean` to reset simulation directories to
post-build state before re-running:

```bash
# Clean all stages and re-run
mdfactory simulate output_dir/ --clean --slurm gpu.yaml

# Clean only Production and re-run it
mdfactory simulate output_dir/ --clean --stages Production --slurm gpu.yaml

# Preview what would be deleted
mdfactory simulate output_dir/ --clean --dry-run
```

The `--clean` flag removes simulation outputs (`.tpr`, `.cpt`, `.log`, `.edr`, `.gro`,
`.xtc`, `.trr`, rescue MDPs, GROMACS backup files) while preserving build inputs
(`system.pdb`, `topology.top`, the generated `.mdp` files, `.itp`, `.yaml`). It respects
the `--stages` filter — only files belonging to requested stages are deleted.

</Accordion>
<Accordion title="grompp: cut-off longer than half the box">

`charmm` builds use the longer nonbonded cutoff of the two schemes (see
[Simulation Settings](/docs/user-guide/simulation-settings#the-generated-protocol)), so every box
edge must be at least about 2.6 nm. grompp reports *"The cut-off length is longer than half the shortest box
vector or longer than the smallest box diagonal element"* for smaller boxes. Increase the
molecule count (mixedbox), the lipid count or `z_padding` (bilayer), or the padding (LNP,
protein types). `sage` builds (`openff`, `amber`) have a shorter cutoff and rarely hit this.

</Accordion>
<Accordion title="Settings changes: duplicate inputs or refused re-renders">

- *"Duplicate build inputs ... differ only in simulation settings outside the identity"*: only
  temperature and pressure define a different system. Two rows that differ only in, for example,
  the production length have the same hash and would build into the same directory. Keep one,
  or change the settings of the built system with `mdfactory apply-settings`.
- *"... is set by mdfactory ... and cannot be overridden"*: a `gromacs_overrides` key is owned by
  a typed setting (use the setting, e.g. `temperature` instead of `ref-t`) or by the build
  (nonbonded block, `tc-grps`, `pcoupltype`, `compressibility`).
- `apply-settings` refuses a directory whose changed stage already has outputs. Delete that
  stage's outputs (`.tpr`, `.cpt`, `.log`, `.edr`, `.gro`, `.xtc`) to rerun it with the new
  settings. See [Simulation Settings](/docs/user-guide/simulation-settings).

</Accordion>
<Accordion title="Simulation fails with LINCS or constraint errors">

MDFactory automatically rescues EM, NVT, and NPT stages that fail with physics errors
(LINCS warnings, exploding box, coordinate constraint failures). On each rescue tier the
step size is halved and `nsteps` is doubled to maintain the same elapsed simulation time,
up to 3 tiers by default.

You will see log messages like:

```
WARNING — RESCUE tier 1/3 for abc123/EM: using em_rescue_t1.mdp
WARNING — RESCUE tier 1 for EM: emstep = 0.01 → 0.005
```

If all rescue tiers are exhausted the simulation is marked as failed. To increase or
decrease the retry budget:

```bash
# Allow up to 5 rescue tiers
mdfactory simulate output_dir/ --max-rescue 5

# Disable rescue entirely
mdfactory simulate output_dir/ --max-rescue 0
```

Production stages are never rescued — by that point the system should be stable.
Infrastructure failures (OOM, SLURM timeout, preemption) are handled separately by
Parsl's built-in retry mechanism (`retries` in the executor config).

</Accordion>
<Accordion title="Analysis SLURM submission fails immediately">

`mdfactory analysis ... --slurm` requires:

- `pip install "mdfactory[submitit]"`
- `--account`

</Accordion>
</Accordions>
