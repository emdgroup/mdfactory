This page documents the YAML input format used by:

```bash
mdfactory build <input.yaml> <output_dir>
```

The YAML is parsed into the `BuildInput` model, which combines:

- top-level run settings (`simulation_type`, `engine`, `parametrization`)
- `system` composition (varies by simulation type)
- optional `simulation_settings` (temperature, pressure, stage lengths, GROMACS overrides)

## Top-level schema

| Key | Required | Type | Notes |
|---|---|---|---|
| `simulation_type` | Yes | string | One of `mixedbox`, `bilayer`, `lnp`, `proteinbox`, `protein_mixedbox` |
| `system` | Yes | object | Shape depends on `simulation_type` |
| `parametrization` | Yes | string or object | Force-field family: `charmm`, `amber` or `openff` (no default). `amber` is for the protein types only, `openff` for the other three. See [Parametrization](/docs/user-guide/parametrization) |
| `engine` | No | string | Currently only `gromacs` (default: `gromacs`) |
| `simulation_settings` | No | object | How the system is run; only `temperature` and `pressure` enter the hash. See [Simulation Settings](/docs/user-guide/simulation-settings) |

## How `system` works

The `system` block is type-dispatched from `simulation_type`:

- `mixedbox` -> `MixedBoxComposition`
- `bilayer` -> `BilayerComposition`
- `lnp` -> `LNPComposition`
- `proteinbox` -> `ProteinBoxComposition`
- `protein_mixedbox` -> `ProteinMixedBoxComposition`

Each type has different required fields and validation rules.

## Species block basics

Most system types include species entries with this pattern:

```yaml
system:
  species:
    - smiles: "CCO"
      resname: ETH
      count: 100
```

Species-level rules:

- `resname` is required and uppercased automatically.
- `resname` max length is 3 characters.
- `smiles` is canonicalized and validated; ambiguous stereochemistry is rejected.
- Each species must include `count` or `fraction`.

Composition-level rules:

- Use either counts for all species or fractions for all species.
- If fractions are used, they must sum exactly to `1.0` and `total_count` is required.
- Zero-count species are removed after validation.

## Parametrization

`parametrization` is required and names a force-field family (`charmm`, `amber` or `openff`).
The shorthand takes every component's family default:

```yaml
parametrization: openff
```

The explicit form overrides individual components:

```yaml
parametrization:
  family: openff
  small_molecules:
    forcefield: openff-2.2.0.offxml
    charge_method: openff-gnn-am1bcc-0.1.0-rc.3.pt
  water_model: opc3
```

Omitted components keep their family default. Unknown top-level keys are rejected. See
[Parametrization](/docs/user-guide/parametrization) for the families, their component options and
the CGenFF requirements of the `charmm` family.

## Simulation settings

`simulation_settings` configures the generated run schedule. Omitted fields take defaults
(300 K, 1 bar, 2 fs, 100 ps NVT and NPT, 100 ns production; 1 µs for `bilayer`):

```yaml
simulation_settings:
  temperature: 310.0                                   # K
  production: {length: 500.0, output_interval: 20.0}   # ns / ps
  gromacs_overrides:
    npt: {pcoupl: C-rescale}
```

A protocol file given with `--simulation-settings` fills the fields that the YAML leaves out.
See [Simulation Settings](/docs/user-guide/simulation-settings) for all fields, validation rules,
overrides and the identity rule.

## Ionization block

All five system types support:

```yaml
ionization:
  neutralize: true
  concentration: 0.15
  min_distance: 5.0
  seed: 42
```

Defaults:

- `neutralize: true`
- `concentration: 0.15`
- `min_distance: 5.0`
- `seed: null`

To disable ionization explicitly, set the field to `null` or `false`:

```yaml
system:
  ionization: false  # `null` is equivalent
```

Both forms skip ion placement. If ionization is omitted, the defaults above are
applied. A configured `concentration: 0.0` with `neutralize: false` likewise leaves
the system unchanged without attempting to add zero ions.

`proteinbox` and `protein_mixedbox` do not accept `false`/`null`: use
`concentration: 0` (no salt) and `neutralize: false` instead. With `neutralize: false`, the
net-charge `grompp` warning is the only one tolerated at build time.

## Full examples by simulation type

These examples intentionally use compounds from the repository example inputs under `examples/` so docs stay aligned with tested/public examples.

<Tabs items={['Mixedbox', 'Bilayer', 'LNP', 'Proteinbox', 'Protein mixedbox']}>
<Tab value="Mixedbox">

```yaml
simulation_type: mixedbox
engine: gromacs
parametrization: openff
system:
  species:
    - smiles: "O"
      resname: SOL
      fraction: 0.90
    - smiles: "CCO"
      resname: ETH
      fraction: 0.10
  total_count: 2000
  target_density: 1.0
  ionization:
    neutralize: true
    concentration: 0.15
```

`MixedBoxComposition` fields:

- `species` (`SingleMoleculeSpecies[]`) required
- `total_count` optional if using counts, required if using fractions
- `target_density` optional, default `1.0`
- `ionization` optional, defaults applied

</Tab>
<Tab value="Bilayer">

```yaml
simulation_type: bilayer
engine: gromacs
parametrization: openff
system:
  species:
    - smiles: "CCCCCCCC/C=C\\CCCCCCCC(=O)OC[C@H](CO[P@](=O)([O-])OCC[N+](C)(C)C)OC(=O)CCCCCCC/C=C\\CCCCCCCC"
      resname: POC
      count: 128
  z_padding: 20.0
  monolayer: false
  ionization:
    neutralize: true
```

`BilayerComposition` fields:

- `species` (`LipidSpecies[]`) required
- `z_padding` optional, default `20.0`
- `monolayer` optional, default `false`
- `ionization` optional, defaults applied

Validation note:

- when `monolayer: false`, each lipid species count must be even.

</Tab>
<Tab value="LNP">

```yaml
simulation_type: lnp
engine: gromacs
parametrization: openff
system:
  radius: 120.0
  shell_thickness: 28.0
  padding: 25.0
  core:
    species:
      - smiles: "CCCCCCCC[C@@H](CCCCCC)C(=O)OCCCCCCN(CCCCO)CCCCCCOC(=O)[C@@H](CCCCCC)CCCCCCCC"
        resname: ALN
        fraction: 0.50
      - smiles: "CCCCCCCC[C@@H](CCCCCC)C(=O)OCCCCCC[N@H+](CCCCO)CCCCCCOC(=O)[C@@H](CCCCCC)CCCCCCCC"
        resname: ALP
        fraction: 0.20
      - smiles: "CC(C)CCC[C@@H](C)[C@H]1CC[C@H]2[C@@H]3CC=C4C[C@@H](O)CC[C@]4(C)[C@H]3CC[C@]12C"
        resname: CHL
        fraction: 0.30
    target_density: 0.95
  shell:
    species:
      - smiles: "CCCCCCCC[C@@H](CCCCCC)C(=O)OCCCCCCN(CCCCO)CCCCCCOC(=O)[C@@H](CCCCCC)CCCCCCCC"
        resname: ALN
        fraction: 0.50
      - smiles: "CCCCCCCCCCCCCCCCCC(=O)OC[C@H](CO[P@](=O)([O-])OCC[N+](C)(C)C)OC(=O)CCCCCCCCCCCCCCCCC"
        resname: DSP
        fraction: 0.10
      - smiles: "CC(C)CCC[C@@H](C)[C@H]1CC[C@H]2[C@@H]3CC=C4C[C@@H](O)CC[C@]4(C)[C@H]3CC[C@]12C"
        resname: CHL
        fraction: 0.38
      - smiles: "CCCCCCCCCCCCCCCN(CCCCCCCCCCCCCC)C(=O)COCCOC"
        resname: PEG
        fraction: 0.02
    z0: 10.0
    area_per_lipid: 65.0
  ionization:
    neutralize: true
```

`LNPComposition` fields:

- `radius` required (`> 0`)
- `shell_thickness` optional, default `28.0`
- `padding` optional, default `25.0`
- `core` required
- `shell` required
- `ionization` optional, defaults applied

LNP-specific behavior:

- core/shell species are fraction-based and must each sum to `1.0`
- counts are computed automatically from geometry/density
- `core_radius = radius - shell_thickness` must stay positive

<Tab value="Proteinbox">

```yaml
simulation_type: proteinbox
engine: gromacs
parametrization:
  family: amber
  protein: amber14sb
  water_model: tip3p
system:
  protein:
    resname: LYZ
    pdb_path: ./1aki.pdb
    chains: [A]
    disulfide_bonds:
      - [CYS6, CYS127]
      - [CYS30, CYS115]
    protonation_states:
      HIS15: HIE
    ignore_hydrogens: true
  padding: 12.0
  relax_steps: 10000
  ionization:
    neutralize: true
    concentration: 0.15
```

`ProteinBoxComposition` fields:

- `protein` (`ProteinSpecies`) required, see below
- `padding` optional, default `10.0` Å (minimum protein-to-box-edge distance)
- `relax_steps` optional, default `10000` (OpenMM steps of the protein-restrained relaxation)
- `ionization` optional, defaults applied

</Tab>
<Tab value="Protein mixedbox">

```yaml
simulation_type: protein_mixedbox
engine: gromacs
parametrization:
  family: amber
  protein: amber14sb
  small_molecules:
    forcefield: openff-2.2.0.offxml
  water_model: tip3p
system:
  protein:
    resname: LYZ
    pdb_path: ./1aki.pdb
    chains: [A]
  species:
    - smiles: O
      resname: SOL
      concentration: 53.0
    - smiles: CCO
      resname: ETH
      concentration: 1.0
  sizing:
    type: fixed_box        # or: count_density (+ target_density)
    box_size: 72.0
  padding: 12.0
  concentration_volume_basis: protein_excluded
  partial_specific_volume: 0.73
  relax_steps: 10000
  ionization:
    neutralize: true
    concentration: 0.15
```

`ProteinMixedBoxComposition` fields:

- `protein` (`ProteinSpecies`) required
- `species` (`SolutionSpecies[]`) required; each has `smiles`, `resname` and exactly one of
  `count` or `concentration` (molar). `fraction` is not accepted. Water is an explicit `smiles: O`
  species; `O` must use `SOL`, `[Na+]` `NA` and `[Cl-]` `CL`
- `sizing` required: `type: fixed_box` with `box_size` (Å; at least protein extent + 2 × `padding`), or
  `type: count_density` with `target_density` (default `1.0` g/cm³; every species needs a `count`)
- `padding` optional, default `10.0` Å
- `concentration_volume_basis` optional: `protein_excluded` (default) or `box`
- `partial_specific_volume` optional, default `0.73` mL/g (used for `protein_excluded`)
- `relax_steps` optional, default `10000`
- `ionization` optional; salt is added on top of neutralization and any packed ions

See the [protein tutorial](/docs/user-guide/tutorial-protein-mixedbox) for a walkthrough.

</Tab>

## Protein species

`system.protein` (`ProteinSpecies`) is shared by both protein types:

| Key | Default | Notes |
|---|---|---|
| `resname` | – | Required, max 3 characters |
| `pdb_path` | – | Required. A relative path is resolved against the YAML (or CSV) file's directory |
| `count`, `fraction` | `1`, `1.0` | Only one protein is supported |
| `chains` | `[]` | Chains to keep. Each becomes a `Protein_chain_<ID>` molecule. Required for multi-chain `proteinbox` inputs |
| `merge_all` | `false` | Merge all chains into one molecule. Required for multi-chain `protein_mixedbox`; cannot be combined with `chains` |
| `disulfide_bonds` | `[]` | Pairs of residues, e.g. `[[CYS6, CYS127]]`; chain-qualified (`A:CYS6`) is allowed |
| `protonation_states` | `{}` | Residue to state, e.g. `HIS15: HIE`. CHARMM translates `HID/HIE/HIP/LYN` to `HSD/HSE/HSP/LSN` |
| `ignore_hydrogens` | `true` | Passes `-ignh` to `pdb2gmx` |

`pdb2gmx` needs GROMACS on `PATH` (or `[gromacs] GMX_PATH`), and `parametrization.protein:
amber14sb` needs GROMACS 2026 or later.

## What happens during parsing

When YAML is loaded:

1. `simulation_type` selects the correct system model.
2. Validation checks species, fractions/counts, and type-specific constraints.
3. Missing defaults are injected (engine, ionization defaults, the family defaults of each parametrization component, and the per-type simulation-settings defaults).
4. A canonical hash is generated from the final normalized model payload. From the simulation settings, only temperature and pressure enter it.

Spelling out a default does not change the hash, but any change of the system, the parametrization or the state point does.

## Common validation failures

- Invalid or ambiguous stereochemistry in SMILES
- `resname` longer than 3 characters
- Mixed usage of counts and fractions in one composition
- Fraction sums not equal to `1.0`
- Missing `total_count` when using fractions in mixedbox/bilayer
- Bilayer odd lipid counts when `monolayer: false`
- `protein_mixedbox`: a species with both or neither of `count`/`concentration`, a `fraction`, or `merge_all` together with `chains`
- A box that is smaller than the protein extent plus 2 × `padding`
- `parametrization` family that does not fit the system type (for example `amber` for `mixedbox`)
- LNP `radius <= shell_thickness`
