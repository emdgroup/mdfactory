---
title: Parametrization
description: Force-field families and per-component parametrization in MDFactory
---

Every build names one **force-field family** in its `parametrization` field. A family is a
coherent combination of force fields, one per system component:

- **protein**: the protein force field passed to `gmx pdb2gmx` (protein systems only)
- **small molecules**: how SMILES species are parametrized
- **water**: the water model
- **ions**: Na⁺/Cl⁻ parameters, which follow from the family (they are not chosen separately)

Each component has a family default and can be overridden. `parametrization` is **required** for
every simulation type; there is no global default.

## Families

| Family | Protein | Small molecules | Water | Ions | Nonbonded scheme | Simulation types |
|--------|---------|-----------------|-------|------|------------------|------------------|
| `charmm` | `charmm36m` | CGenFF | `tip3p` | CHARMM (`ions.itp`) | `charmm` (Force-switch) | all five |
| `amber` | `amber14sb` | OpenFF Sage | `tip3p` | Joung–Cheatham (`ions_tip3p.itp`) | `sage` (Potential-switch, `DispCorr EnerPres`) | `proteinbox`, `protein_mixedbox` |
| `openff` | n/a | OpenFF Sage | `opc3` | from the Sage `.offxml` | `sage` | `mixedbox`, `bilayer`, `lnp` |

The **nonbonded scheme** sets the nonbonded block of the generated run schedule, identical in all
four stages and for every simulation type:

- `charmm`: PME with `rcoulomb = 1.2`, `vdwtype = cutoff`, `vdw-modifier = Force-switch` from
  `rvdw-switch = 1.0` to `rvdw = 1.2`, as all CHARMM36/CGenFF parameter files specify.
  `DispCorr = EnerPres` for `mixedbox` and `lnp`, `no` for `bilayer` and the protein types
  (CHARMM lipids and proteins were parametrized without a long-range correction).
- `sage`: PME with `rcoulomb = 0.9`, `vdwtype = cutoff`, `vdw-modifier = Potential-switch`
  from `rvdw-switch = 0.8` to `rvdw = 0.9`, and `DispCorr = EnerPres`. These are the cutoff and
  switch of the Sage `.offxml` files, which OpenFF treats as part of the force field.

See [Simulation Settings](/docs/user-guide/simulation-settings) for the rest of the protocol and
how to configure it.

<Callout type="info" title="Box size with the CHARMM cutoff">
The 1.2 nm CHARMM cutoff needs a box edge of at least about 2.6 nm (twice the pair-list
radius). The repository examples are far larger.
</Callout>

## Syntax

The shorthand takes every component's family default:

```yaml
parametrization: amber
```

The explicit form overrides individual components. Components that are omitted keep their family
default:

```yaml
parametrization:
  family: amber              # charmm | amber | openff (required)
  protein: amber14sb         # protein types only
  small_molecules:           # not allowed for proteinbox
    forcefield: openff-2.2.0.offxml
    charge_method: openff-gnn-am1bcc-0.1.0-rc.3.pt
  water_model: tip3p
```

The shorthand and the fully spelled-out defaults describe the same build and have the same hash.
After validation, components that do not apply to the simulation type are stored as `null`
(for example `protein` in a `mixedbox`, or `small_molecules` in a `proteinbox`). Setting such a
component is an error.

`water_model` is always a **water model name** (`tip3p`, `opc3`, `spce`, ...). Depending on the
family it selects the `pdb2gmx -water` model, the native `<name>.itp` of the force field, or the
OpenFF `<name>.offxml` file. A value ending in `.offxml` is rejected.

The protein-preparation options `ignore_hydrogens` and `merge_all` are not part of the
parametrization. They live on `system.protein`; see [System Types](/docs/user-guide/system-types).

### Component options

| Component | Families | Default | Allowed values |
|-----------|----------|---------|----------------|
| `protein` | `charmm` | `charmm36m` | CHARMM force fields without LJ-PME (e.g. `charmm36m`, `charmm27`) for `proteinbox`; only `charmm36m` for `protein_mixedbox` |
| `protein` | `amber` | `amber14sb` | only `amber14sb` |
| `small_molecules.forcefield` | `charmm` | `cgenff` | only `cgenff` |
| `small_molecules.forcefield` | `amber`, `openff` | `openff-2.2.0.offxml` | any OpenFF `.offxml`, e.g. `openff_unconstrained-2.2.0.offxml` |
| `small_molecules.charge_method` | `amber`, `openff` | `openff-gnn-am1bcc-0.1.0-rc.3.pt` | a NAGL model file, `nagl` (alias of the default model), `am1bcc`, `am1bccelf10` |
| `water_model` | `charmm` | `tip3p` | `tip3p`, `spc`, `spce` for `proteinbox`; only `tip3p` otherwise |
| `water_model` | `amber` | `tip3p` | only `tip3p` |
| `water_model` | `openff` | `opc3` | any OpenFF water model name, e.g. `tip3p`, `tip3p_fb`, `tip4p_fb`, `spce` |

## The `charmm` family

CHARMM36m for proteins, CGenFF for small molecules, and the CHARMM TIP3P water and ions.

<Callout type="warn" title="Third-party software">
CGenFF is third-party software developed by SilcsBio / University of Maryland and is **not included** with MDFactory.
A separate [CGenFF license](https://cgenff.silcsbio.com/) is required for small molecules
(`proteinbox` builds need no CGenFF).
</Callout>

- Small molecules need a CGenFF installation (`SILCSBIODIR` in `config.ini`).
- In `mixedbox`, `bilayer` and `lnp`, water and ions come from the `charmm36.ff` of the CGenFF
  installation. In protein systems they come from the bundled protein force field.
- Well validated for drug-like molecules and compatible with the CHARMM36 lipid and protein force fields.

```yaml
parametrization: charmm
```

## The `amber` family (protein systems)

A fully open-source route for `proteinbox` and `protein_mixedbox` that needs no CGenFF or SILCSBIO
license:

- **Protein:** Amber ff14SB, using the `amber14sb.ff` force field that ships with GROMACS, through `gmx pdb2gmx`.
- **Small-molecule solutes** (`protein_mixedbox`): OpenFF Sage through SMIRNOFF.
- **Water and ions:** TIP3P and Joung–Cheatham Na⁺/Cl⁻ from `amber14sb.ff`.

<Callout type="warn" title="Requires GROMACS 2026 or later">
`amber14sb.ff` is only shipped with, and only correct for, GROMACS ≥ 2026 (older versions silently
ignore its LEaP dihedral reordering). MDFactory checks the `gmx` version before `pdb2gmx` at build
time and again before the first `grompp` of `mdfactory simulate`, on the node that runs the job.
Use the pixi `gmx` environment (`pixi run -e gmx ...`, or `gmx-cuda` for the CUDA build) or point
`[gromacs] GMX_PATH` at a GROMACS 2026 binary.
</Callout>

```yaml
parametrization:
  family: amber
  small_molecules:
    charge_method: nagl
```

Protonation states use Amber residue names directly (e.g. `HIE`, `HID`, `HIP`).

## The `openff` family

OpenFF Sage for every small molecule, with OpenFF water and ions, for `mixedbox`, `bilayer` and `lnp`.

- Modern, well-maintained force field (OpenFF 2.x "Sage") with automatic atom typing from SMILES
- Fast neural-network partial charges (NAGL)
- No external license required

```yaml
parametrization:
  family: openff
  water_model: tip3p
```

### Charge methods

<Tabs items={['NAGL (Fast)', 'AM1-BCC (Standard)']}>
<Tab value="NAGL (Fast)">

NAGL uses a graph neural network trained on AM1-BCC charges. It is much faster than
quantum-mechanical methods (typically ~0.1 s per molecule).

```yaml
parametrization:
  family: openff
  small_molecules:
    charge_method: nagl   # alias of openff-gnn-am1bcc-0.1.0-rc.3.pt
```

</Tab>
<Tab value="AM1-BCC (Standard)">

Standard AM1-BCC uses semi-empirical quantum mechanics (typically 1–30 s per molecule).
Use `am1bccelf10` for better conformer handling.

```yaml
parametrization:
  family: openff
  small_molecules:
    charge_method: am1bcc
```

</Tab>
</Tabs>

## Choosing a family

| Use case | Family |
|----------|--------|
| General small molecules, quick prototyping, no license | `openff` |
| Lipid bilayers compatible with CHARMM36 | `charmm` |
| Compatibility with existing CHARMM systems | `charmm` |
| Protein systems with CHARMM36m | `charmm` |
| Protein systems without a CGenFF license | `amber` (GROMACS ≥ 2026) |

## Parameter caching

Generated small-molecule, water and ion parameters are cached in the parameter store
(`[storage] PARAMETERS` in `config.ini`):

```
<parameter store>/
└── gromacs/
    ├── cgenff/
    │   └── {molecule_hash}/
    │       ├── {molecule_hash}.itp
    │       └── {molecule_hash}_extra_params.itp
    └── openff/
        ├── small_molecules/
        │   └── {forcefield}_{key_digest}/
        │       └── {molecule_hash}/
        ├── water/
        │   └── {water_model}_{key_digest}/
        └── ions/
            └── {forcefield}_{key_digest}/
                ├── NA/
                └── CL/
```

- **OpenFF small molecules** are keyed on the force field, the resolved charge method (`nagl` and
  the default NAGL model file share an entry) and an internal cache-format version. Changing the
  force field or the charge method never reuses an entry made with other settings.
- **OpenFF water** is keyed on the water model, **OpenFF ions** on the force field.
- Each OpenFF entry holds the moleculetype `.itp`, the atom types, the merged `_params.itp` and a
  `provenance.json` with the key inputs and the installed `openff-toolkit` and
  `openff-interchange` versions (recorded for reference, not part of the key).
- An entry is reused only if all files exist and its completion marker (`.complete`, written
  last) is present. An interrupted or failed entry is removed and regenerated.
- Each entry directory is locked while it is checked and written, so concurrent builds do not
  parametrize the same molecule twice.
- Native water and ions (from a CHARMM or Amber force-field directory) are never cached.

### OpenFF atom-type names

OpenFF atom types are private to each molecule. MDFactory renames them to
`<prefix>_<index>`, where the prefix (`T` plus nine hex digits) is derived from the molecule and
its cache key. Two different molecules therefore never share atom-type names, even when they
were parametrized with the same residue name. Atom names are not changed.

## Parameter set structure

Each parametrized species produces a `GromacsSingleMoleculeParameterSet`:

| Field | Description |
|-------|-------------|
| `moleculetype` | GROMACS moleculetype name (molecule hash, or `SOL`/`NA`/`CL`) |
| `smiles` | Canonical SMILES string |
| `component` | `small_molecule`, `water` or `ion` |
| `forcefield` | Force field that produced the set (e.g. `cgenff`, `openff-2.2.0.offxml`, `opc3.offxml`, `amber14sb`) |
| `charge_method` | Resolved charge method (OpenFF small molecules only) |
| `water_model` | Water model of water sets and of water-specific ions (Amber `ions_tip3p.itp`) |
| `topology_merge` | How the set is combined into a topology: `cgenff`, `smirnoff` or `native` |
| `itp` | Path to the molecule's ITP file |
| `parameter_itp` | Path to the extra parameters ITP (`None` for native water/ions) |
| `forcefield_itp` | Path to the force field's `forcefield.itp` (CGenFF and native sets) |

## Migrating from the old keys

The flat `parametrization: cgenff | smirnoff | pdb2gmx` values and the `parametrization_config`
block were removed. They are rejected with a validation error:

| Old | New |
|-----|-----|
| `parametrization: cgenff` | `parametrization: charmm` |
| `parametrization: smirnoff` | `parametrization: openff` |
| `parametrization: pdb2gmx` | `parametrization: charmm` |
| `parametrization_config.forcefield` (protein) | `parametrization.protein` |
| `parametrization_config.water_model: opc3.offxml` | `parametrization.water_model: opc3` |
| `parametrization_config.forcefield` / `sage_forcefield` (OpenFF) | `parametrization.small_molecules.forcefield` |
| `parametrization_config.charge_method` | `parametrization.small_molecules.charge_method` |
| `parametrization_config.ignore_hydrogens` / `merge_all` | `system.protein.ignore_hydrogens` / `system.protein.merge_all` |

This is a clean break: build hashes change, and old build directories, run-database rows
(`input_data`) and pushed data cannot be parsed into the new `BuildInput`. Old OpenFF cache
entries under `parameter_store/gromacs/smirnoff/` are not reused; OpenFF parameters (including
NAGL/AM1-BCC charges) are regenerated once under `gromacs/openff/`. The CGenFF cache under
`gromacs/cgenff/` is unchanged and still valid.

## Troubleshooting

### OpenFF issues

**"No conformer available"**

The molecule needs a 3D conformer for charge assignment. This is handled automatically during parametrization, but may fail for very large or unusual molecules.

**"Unsupported atom type"**

Some exotic atoms may not be covered by OpenFF. Check the [OpenFF coverage](https://openforcefield.org/force-fields/force-fields/).

### CGenFF issues

**"SILCSBIODIR not set"**

Configure the CGenFF installation path in `config.ini`:

```ini
[cgenff]
SILCSBIODIR = /path/to/silcsbio
```

**High penalty scores**

CGenFF penalty scores indicate parameter quality. Scores > 50 may indicate unreliable parameters.
